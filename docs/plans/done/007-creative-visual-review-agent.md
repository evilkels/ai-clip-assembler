# Plan 007: Make the In-App Review Agent a visual creative curator

## Status

- **Status**: DONE (2026-06-21) | **Priority**: P1 | **Effort**: L | **Risk**: MED-HIGH
- **Depends on**: 005, 006 | **Planned at**: commit `6744eaa`, 2026-06-21

## Why this matters

The agent was text-only and stateless: raw candidate/timeline JSON, forced into
one short sentence, no Frame Samples. The Version gallery was generated by
fixed frontend recipes — the "creative agent" never actually chose footage.
After plans 005 (rich candidate pool) and 006 (persisted sessions), the agent
can compare visual moments and propose coherent cuts, while deterministic
technical analysis stays authoritative for motion quality.

## Decisions / target design

Deterministic code owns technical filtering/validation; Pi owns semantic
visual judgment and creative sequencing. The agent receives recent persisted
conversation + rolling summary, Candidate Clip metadata, a bounded/labelled
set of representative Frame Samples (<=12 images, Scene-diverse, no more than
one call's worth of absolute paths — never persisted), and the current
Timeline Document/Versions. It may return a message, 0-1 validated Operation
Proposal, and 2-4 validated preview-spec Versions. Model output (IDs, bounds,
speeds, transforms, counts) is never trusted — all validated against Candidate
Clips/source durations before persisting or rendering. Still frames were
re-scoped to judge Visual Interest/composition/tags only; Smoothness Score
stays deterministic (vidstab/OpenCV), not inferred from stills. Manual Harness
projects must never send Frame Samples or invoke a cloud model — they keep the
deterministic `mockVersions.ts`-equivalent fallback, which also serves as the
graceful degradation path when model output is invalid/unavailable.

## Maintenance notes

Changing the prompt/model invalidates the existing Pi score cache. Review
focus areas: privacy mode (no Frame Samples for Manual Harness), context
bounds, hallucination rejection, deterministic fallback, and whether follow-up
turns genuinely reuse persisted history rather than only the latest message.
